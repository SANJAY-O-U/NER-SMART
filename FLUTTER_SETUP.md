# FLUTTER_SETUP.md — Initializing the Driver App Locally

The `flutter_app/` folder in this package contains only the Dart
application code (`lib/`) and `pubspec.yaml`. It does **not** contain the
native Android/iOS project scaffolding (`android/`, `ios/`, gradle files,
`Info.plist`, etc.) — that must be generated by a real Flutter SDK, which
is not available in the environment this project was packaged in.

Hand-writing that native scaffolding is fragile and version-dependent, so
`flutter create` is the correct and only reliable way to generate it.

## 1. Flutter SDK requirement

Install the Flutter SDK (stable channel) if you don't already have it:
https://docs.flutter.dev/get-started/install

Verify:
```bash
flutter doctor
```
Resolve any red ✗ items relevant to the platform you'll run on (Android
Studio + SDK for Android, Xcode for iOS).

## 2. Generate the native project (in place)

```bash
cd flutter_app
flutter create .
```
This adds `android/`, `ios/`, `web/`, etc. around your existing `lib/` and
`pubspec.yaml` without touching them.

```bash
flutter pub get
```

Phase 5 added `sqflite`, `connectivity_plus`, and `uuid` to `pubspec.yaml` —
`flutter pub get` installs them automatically; no additional native
permissions are required beyond the ones below.

## 3. Android setup — required permissions

Open `android/app/src/main/AndroidManifest.xml` and add these inside
`<manifest>`, before `<application>`:
```xml
<uses-permission android:name="android.permission.INTERNET" />
<uses-permission android:name="android.permission.ACCESS_FINE_LOCATION" />
<uses-permission android:name="android.permission.ACCESS_COARSE_LOCATION" />
```

If you skip the location permissions, the app still works end-to-end — it
automatically falls back to a fixed demo coordinate (see
`lib/services/location_service.dart`) and labels it clearly in the UI.

## 4. iOS permissions (only if you're building for iOS/simulator)

Open `ios/Runner/Info.plist` and add inside the top-level `<dict>`:
```xml
<key>NSLocationWhenInUseUsageDescription</key>
<string>NER-SMART needs your location to attach it to an incident report.</string>
```

## 5. Configure the backend base URL

The URL is a build-time setting (`NER_API_BASE_URL`, read by
`lib/config/app_config.dart`) — no source edit needed.

| Target                | How to run / build |
|------------------------|--------------------|
| Android emulator       | `flutter run` (debug default: `http://10.0.2.2:5000/api`) |
| iOS simulator          | `flutter run --dart-define=NER_API_BASE_URL=http://127.0.0.1:5000/api` |
| Physical device (dev)  | `flutter run --dart-define=NER_API_BASE_URL=http://<your-machine-LAN-IP>:5000/api` — device and backend on the same Wi-Fi, firewall must allow port 5000 |
| Production release     | `flutter build apk --release --dart-define=NER_API_BASE_URL=https://<backend-host>/api` |

Release builds fail closed: without `NER_API_BASE_URL`, or with a
non-HTTPS URL, the app shows a configuration error and makes no network
calls. Plain-HTTP dev URLs work only in debug/profile builds (cleartext is
allowed only by `android/app/src/debug/AndroidManifest.xml`). The app
carries no API key or other secret.

## 6. Run

```bash
flutter devices        # confirm an emulator/device is attached
flutter run
```

The backend (see DEMO_RUN.md) must already be running and reachable at the
URL you configured, or incident submission will fail with a clear
"could not reach the backend" message in the app.
